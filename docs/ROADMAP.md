# Neon Stack Roadmap

本路线图记录 Neon Stack 的改进方向，供开发和体验验收使用。条目按优先级推进，尚未承诺发布时间；未勾选的条目均为计划。

## 当前基础

- [x] RealityKit 棋盘、霓虹方块、落点投影及消行动效。
- [x] 单人挑战和本地同屏双人对战。
- [x] 七袋方块序列、SRS 旋转、暂存、五块预览及锁定延迟。
- [x] 同序列对战、垃圾行攻击、连击与攻击抵消。
- [x] 键盘和 GameController 输入、暂停及断连处理。
- [x] Liquid Glass 操作按钮及原生设置窗口。
- [x] 随等级切换的原创合成 BGM、不同消行数的音效、独立音频开关和音量保存。
- [x] 规则、音频播放和动效生命周期的自动化测试。

双实体手柄的绑定、长按连移、断连和重连尚未完成实机验收。当前应用使用本地临时签名，尚未公证。

## P0：操作手感与对战反馈

目标：让输入稳定可控，让玩家清楚理解攻击、抵消和胜负。

| 计划 | 验收标准 |
| --- | --- |
| 双实体手柄实机验收 | 两位玩家独立操作；单人忽略第二只手柄；断连暂停、重连后可继续；连续多局无绑定串位 |
| 输入设置 | 支持键盘与手柄映射、长按首次延迟、连续移动间隔和摇杆死区；设置可保存和恢复默认 |
| 手柄完整导航 | 无需鼠标即可选择模式、开始、暂停、继续、重新开始、返回大厅及访问设置；焦点清晰 |
| 开局倒计时 | 开始与重新开局显示三秒倒计时；倒计时结束前不接受棋盘操作 |
| 攻击与垃圾行提示 | 清楚显示发送量、抵消量和待接收量；垃圾行进入前有提示，且不遮挡落点 |
| 危险状态提示 | 接近堆顶时提供边缘颜色和轻量声音提示；避免持续闪烁，可关闭声音 |
| 主操作按钮辨识度 | 开始、继续及模式选中态在大厅、游戏和暂停背景下均清晰；禁用态明确；旧系统回退样式可用 |

## P1：持续游玩的目标

目标：让单人有可重复挑战的目标，让双人对战形成完整比赛。

| 计划 | 验收标准 |
| --- | --- |
| 本地最高分与历史成绩 | 按模式保存成绩；结果页提示新纪录；重启后保留；提供清理入口 |
| 40 行竞速 | 消除 40 行后结算用时，保存最佳成绩；暂停时间处理规则明确 |
| 限时挑战 | 在固定时间内比拼得分，明确倒计时和结束条件；成绩与其他模式分开记录 |
| 双人三局两胜 | 显示局分，每局结算后进入下一局；最终显示比赛胜者；可重新比赛或返回大厅 |
| 结果页统计 | 单人展示得分、用时、消行数、每分钟消行数及四行消除次数；双人补充双方攻击量和局分 |
| 首次操作引导 | 根据键盘或手柄展示对应说明；可跳过和重新查看；不阻碍熟练玩家开局 |

建议下一轮优先实现本地最高分、40 行竞速和双人三局两胜。

## P2：玩法深度与视听表现

目标：奖励高阶操作，同时保持棋盘可读性和长时间游玩的舒适度。

| 计划 | 验收标准 |
| --- | --- |
| T-spin、全清和完整 Back-to-back 奖励 | 先明确判定、计分和攻击规则；测试覆盖正例、反例、连续奖励及中断条件；界面展示奖励来源 |
| 活动方块与投影区分 | 活动、锁定和投影方块在颜色、亮度或轮廓上可区分，降低只依靠颜色识别的负担 |
| 动效层级优化 | 普通消行、四行消除、连击和全清形成层级；不遮挡下一块落点；减少动效模式保留关键信息 |
| 操作音效与震动 | 增加轻量旋转、锁定和硬降反馈；避免长按声音堆叠；音效与震动可独立控制，验证支持的实体手柄 |
| 音乐与音效混音 | 消行时短暂降低 BGM 音量并平滑恢复；双人同时消行避免峰值过高；静音和暂停行为一致 |
| 长时间音乐体验 | 实际试听等级切换及长期循环，改善旋律变化和重复感；保留交叉淡入淡出 |
| 游戏中信息布局 | 将单人右侧常驻说明调整为目标或纪录；操作说明仍可随时查看 |
| 动效设置归整 | 将减少动效等选项纳入设置并保存，尊重系统减少动态效果设置 |

## P3：产品完整度与发布

- [ ] 优化小窗口布局，检查文字、预览和控件是否溢出。
- [ ] 检查键盘焦点、VoiceOver 标签、文字对比度和颜色辨识。
- [ ] 在高等级、双人连续消行和长时间运行下测量帧耗时、输入延迟及内存占用。
- [ ] 增加可重复的构建与测试流程，明确支持的 macOS 和硬件范围。
- [ ] 准备版本号、发布说明、正式签名与公证，验证安装和启动流程。
- [ ] 评估联网对战、排行榜和回放；明确同步、延迟、隐私及维护成本后再决定范围。

## 开发与验收原则

1. 规则和计分变化先明确行为，再以确定性测试验证；渲染和音效不得改变碰撞与胜负判定。
2. 交互变化需要在真实窗口中检查；手柄功能需要实体设备验收，不能以键盘测试替代。
3. 音频既验证播放状态，也检查真实听感；视觉反馈检查高强度场景和减少动效模式。
4. 每个条目完成实现与验收后再勾选；环境限制和未验证事项保留在文档中。
